# 04 · 开机接管与守护

系统应用装好之后，**主页键**已经是自己的了。剩下的问题是**开机**：固件仍然先画聚好看。

这一篇讲怎么把开机也接管过来，以及代价。

---

## 为什么开机还会先看到聚好看

开机动画的退出条件是「**有应用窗口被绘制**」，不是时间到。而这台固件在任何第三方组件可启动之前，
就先起了聚好看——它占住了第一帧。

实测时间线（logcat）：

```
08:00:19.795  START u0 {act=MAIN cat=[HOME] ... cmp=com.jamdeo.tv.vod/...LauncherActivity} from uid 0
08:00:20.004  START u0 {flg=0x10000000 cmp=com.local.tvhome/.MainActivity} from uid 0   ← 固件也起了我们
```

看起来两个都起了，但此时第三方包其实**还不能被启动**，直接 `am start` 会报：

```
Error: Activity class {com.local.tvhome/com.local.tvhome.MainActivity} does not exist.
```

这个窗口大约持续到 `boot_completed` 之后 **8–10 秒**。所以"开机就拉起"的方案必须带重试。

---

## 方案一（默认）：极简开机钩子，只工作 90 秒

特点：**没有常驻进程、默认不写日志**。开机后逐秒盯前台，一旦聚好看上来就切走并清掉它的进程，然后退出。

`scripts/rc-minimal.sh`：

```sh
#!/system/bin/sh
# 极简开机钩子：轮询 + 重试；最多工作 90 秒，之后退出
LOG=/data/local/misc/rc.log
if [ -f /data/local/misc/debug ]; then
  exec > "$LOG" 2>&1
  chmod 666 "$LOG"
else
  exec > /dev/null 2>&1
fi
VODC=com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity
VODPKG=com.jamdeo.tv.vod
TVH=com.local.tvhome/.MainActivity

# 清理历史遗留的看护/日志进程
for p in $(ps -A -o PID,ARGS 2>/dev/null | grep -E "homewatcher\.sh" | grep -v grep | awk '{print $1}'); do
  kill -9 "$p" 2>/dev/null
done

top_activity() {
  dumpsys activity activities 2>/dev/null | grep -m1 mResumedActivity
}

switch_with_retry() {
  i=0
  while [ $i -lt 6 ]; do
    i=$((i+1))
    am start -n "$TVH" 2>&1 | tail -1
    sleep 2
    case "$(top_activity)" in
      *tvhome*) return 0 ;;
    esac
  done
  return 1
}

# 1) 保证聚好看组件启用（否则开机画不出界面、走不完启动）
pm enable --user 0 "$VODC"

# 2) 逐秒盯 90 秒：聚好看一成为前台就切走
k=0
while [ $k -lt 90 ]; do
  k=$((k+1))
  case "$(top_activity)" in
    *com.jamdeo.tv.vod*)
      switch_with_retry
      sleep 1
      am force-stop "$VODPKG"
      break
      ;;
  esac
  sleep 1
done

# 3) 收尾：只要聚好看不在前台就清掉它的进程
case "$(top_activity)" in
  *com.jamdeo.tv.vod*) : ;;
  *) am force-stop "$VODPKG" ;;
esac

# 4) 非 debug 模式不留日志
[ -f /data/local/misc/debug ] || rm -f "$LOG"
```

### 部署

```powershell
adb push scripts\rc-minimal.sh /data/local/misc/rc.sh
adb shell 'chmod 644 /data/local/misc/rc.sh'
adb reboot
```

### 效果

| 项 | 结果 |
|---|---|
| 开机 | 聚好看约 8–10 秒 → TvHome |
| 常驻进程 | 0 |
| 日志 | 无（放一个 `/data/local/misc/debug` 文件才写 `rc.log`） |
| 主页键 | 直接进 TvHome（系统应用 + priority 100 生效，不需要钩子参与） |

## 方案二（可选）：常驻看护进程，切换更快

如果不满意开机那 8–10 秒，可以换成常驻看护：监听 `ActivityManager: START ... cmp=聚好看`，
一出现就切。实测**约 1 秒**，代价是常驻一个 shell + 一条 logcat，并且会持续写日志（除非关掉）。

`scripts/homewatcher.sh` 是完整实现，要点：

- **不要用 events 缓冲区**（`logcat -b events -s am_resume_activity`）：在这台机器上重启后该事件为 0 条，
  看护完全不触发。改用 `logcat -b system -s ActivityManager` 匹配 `START ... cmp=聚好看`。
- **必须加 `-T 1`**：否则 logcat 重启时会把整段历史重放，把用户当前界面误切走。
- 带 10 秒兜底轮询 + logcat 死了自动重启。
- 配合 `scripts/rc-watchdog.sh` 使用时，它还会在开机时启动守护循环，进程死了自动补活。

### 两种方案怎么选

| | 极简钩子 | 常驻看护 |
|---|---|---|
| 开机亮屏到自己的桌面 | 8–10 秒 | 约 1 秒 |
| 常驻进程 | 无 | 1 个 shell + 1 个 logcat |
| 日志 | 默认无 | 默认有（可关） |
| 适用 | 日常使用、想干净 | 追求"一开机就是我桌面" |

**本仓库默认推荐极简钩子**。切换时把对应脚本推到 `/data/local/misc/rc.sh` 即可，注意 `rc-watchdog.sh`
是"看门狗版"，开启后会自动拉起 `homewatcher.sh`（需要把 `homewatcher.sh` 也放到 `/data/local/misc/`）。

## 顺带解决内存：清掉聚好看的进程

聚好看常驻一个 KeepAliveService，`am kill` 杀不掉（进程被服务托住）。要用 `am force-stop`：

```console
adb shell am force-stop com.jamdeo.tv.vod
```

实测：

| 指标 | 清理前 | 清理后 |
|---|---|---|
| 聚好看 PSS | 179–217 MB | 0 |
| `MemAvailable` | 约 678 MB | 约 834 MB |

注意两点：

1. 只杀进程，**不动包和组件**，所以下次开机会被系统重新拉起（钩子会再切一次）；
2. 用户从"全部应用"打开聚好看时会冷启动，几秒才能显示，属正常。

## 安全设计：看门狗

如果实验改错了东西（比如前面说的禁用聚好看组件），开机可能永远走不完。为此可以加一个**dead-man**：
钩子启动后 180 秒检查一次，如果 `boot_completed` 不是 1 或者没有前台界面，就自动恢复。

`scripts/rc-watchdog.sh` 里的实现要点：

```sh
WATCHDOG='sleep 180
B=$(getprop sys.boot_completed)
T=$(dumpsys activity activities 2>/dev/null | grep -m1 mResumedActivity)
if [ "$B" != "1" ] || [ -z "$T" ]; then
  pm enable --user 0 com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity
  am start -a android.intent.action.MAIN -c android.intent.category.HOME
fi'
setsid /system/bin/sh -c "$WATCHDOG" >/dev/null 2>&1 &
```

这个看门狗在调试期间**救回来三次**（每次都是实验把开机搞挂）。如果你要自己试新东西，强烈建议先把它装上。

## 日志开关

所有脚本默认静默。想看日志时：

```console
adb shell 'touch /data/local/misc/debug'
# 复现问题后
adb shell 'cat /data/local/misc/rc.log'
# 看完删掉
adb shell 'rm -f /data/local/misc/debug /data/local/misc/rc.log'
```
