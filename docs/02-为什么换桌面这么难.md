# 02 · 为什么换桌面这么难

这是整个项目最重要的一篇。**如果你只想记一句话：这台固件上，不 root 就换不了默认桌面，而且千万不要禁用聚好看的桌面组件。**

下面是 7 条失败路径，以及它们背后真正的机制。按这个顺序试过，每条都有命令和现象。

---

## 7 条不 root 的路径

| # | 尝试 | 命令 | 结果 |
|---|---|---|---|
| 1 | 看 HOME 候选 | `cmd package query-activities --brief -a android.intent.action.MAIN -c android.intent.category.HOME` | 聚好看 `priority=50`，第三方桌面 `priority=0` |
| 2 | 指定首选桌面 | `cmd package set-home-activity --user 0 <桌面>/.MainActivity` | 返回 `Success`，**不生效**；只写进 `always="false"`，HOME 仍进聚好看 |
| 3 | 改厂商启动指针 | `settings put system settings_startup_source_custom_pkg_key <桌面>`（`startup_source_is_custom` 本来就是 `1`） | **无效**，两次预置重启后开机仍解析到聚好看 |
| 4 | 禁用聚好看桌面组件 | `pm disable --user 0 com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity` | 主页键失效，**并且开机永远走不完** |
| 5 | 换系统自带兜底桌面 | `pm enable com.android.settings`（放出 `.FallbackHome`）+ 禁用聚好看组件 | 开机会解析到 `FallbackHome`，但它反复 finish/重启，开机仍走不完 |
| 6 | 无障碍守护 | 第三方服务监听 `TYPE_WINDOW_STATE_CHANGED` | 服务能绑定，但**收不到聚好看的窗口事件** |
| 7 | 用 adb 模拟主页键 | `input keyevent 3` | **被固件吞掉**：组件启用/禁用两种情况都不产生任何 `START`，只能实体遥控器验证 |

---

## 机制解释

### 1. 第三方 HOME 的 priority 被钳成 0

固件在扫描包时把「非系统应用」的 HOME intent-filter priority 归零，聚好看是系统应用、保持 50。
所以只要聚好看还在候选里，普通解析永远选它。

**这条在把桌面装成系统应用之后消失**：`/system/priv-app` 里的包 priority 保得住（实测 100）。

### 2. `set-home-activity` 写的是"非始终"

`cmd package set-home-activity` 返回 `Success` 会让人以为成功了。但去看
`/data/system/users/0/package-restrictions.xml`，只多出一条 `always="false"` 的 preferred-activity，
它不参与优先级的比较，因此 HOME 仍然解析到聚好看。

### 3. `settings_startup_source_custom_pkg_key` 只是记账值

这个键在 `system` 命名空间，值一直指向聚好看；`/data/local/misc/startup_source_is_custom` 原本就是 `1`。
把它改成自己的桌面、连续两次预置重启，开机启动仍然解析到聚好看。它对开机桌面没有影响。

### 4. 禁用聚好看组件 = 开机卡死（最危险的一条）

正常开机是一条**隐式** HOME 启动：

```
I ActivityManager: START u0 {act=android.intent.action.MAIN cat=[android.intent.category.HOME]
  flg=0x10000100 cmp=com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity} from uid 0
```

把 `LauncherActivity` 组件禁用后，**这条 START 根本不发出**。没有应用窗口被绘制 → 开机动画拿不到第一帧
→ 不退出 → `sys.boot_completed` 一直是空。实测两次开机、每 15 秒采样、共 4 分钟，全部为空。

它不是"桌面找不到"，而是"没有任何窗口可画"。**没有 root 救不回来**（要重新启用组件，只能从特权 shell 进）。

### 5. FallbackHome 能证明"走的是隐式解析"，但救不了场

把系统自带的 `com.android.settings/.FallbackHome` 放出来之后，开机确实会解析到它：

```
START u0 {act=android.intent.action.MAIN cat=[android.intent.category.HOME]
  flg=0x10000100 cmp=com.android.settings/.FallbackHome} from uid 0
```

这证明开机路径是标准的隐式 HOME intent，不是硬编码组件。但 FallbackHome 是"过渡转圈页"：发现没有真桌面
→ `Force finishing` → 系统又把它拉起来，循环，开机照样走不完。

### 6. 无障碍守护收不到事件

和 aerial-tv 里 Vidda C1S（#545）的记录一致：固件不向第三方无障碍服务派发聚好看的
`TYPE_WINDOW_STATE_CHANGED`。守护服务能绑定，但永远等不到窗口变化，拉不回前台。

另外海信在 `boot_completed` 之前会拦截第三方进程（`VtInterceptApp`），第三方 `BootReceiver` 也收不到
`BOOT_COMPLETED`，所以"开机自启再抢前台"这条路也不成立。

### 7. `input keyevent 3` 不可信

注入的主页键在这台机器上被吞：无论聚好看组件启用还是禁用，logcat 里都没有对应的 `START`。
**所有关于主页键的结论都必须用实体遥控器验证**，否则会得出完全相反的判断（我就因此误判过一次）。

---

## 那 root 之后为什么就成了

因为缺的从来不是"解析"，而是"资格"：

1. 装进 `/system/priv-app/<目录>/<包名>.apk` 之后，包变成系统应用（`flags=[SYSTEM]`），
   priority 不再被钳，`resolve-activity` 开始返回它；
2. 于是**实体遥控器按主页键直接进入**，不再经过聚好看；
3. 开机仍然先画聚好看（它占第一帧），但第三方应用在 `boot_completed` 之后约 8–10 秒就可启动，
   用一个小钩子重试 `am start` 就能切过去。

细节见 [03-根权限通道.md](03-根权限通道.md) 和 [04-开机接管与守护.md](04-开机接管与守护.md)。

## 给同代海信用户的建议

| 你的情况 | 建议 |
|---|---|
| 不想 root | 保留聚好看当默认桌面，把自制桌面放图标/自定义键；**绝对不要 `pm disable` 聚好看桌面组件** |
| 愿意 root、能承担写 `/system` | 走系统应用 + priority 100 + 开机钩子 |
| 只想确认"是不是我这台的问题" | 跑一遍上面表格里的 1、2、7 三条命令，能快速判断 |

另外有一条**还没测**的线索：`persist.vt.use_home_pkg`。aerial-tv 的记录里，Android 11 的 MT9653 海信机型
可以用它直接指定主屏幕包，不需要 root。本机 Android 9 是否存在这个属性、是否生效还没验证：

```console
adb shell getprop persist.vt.use_home_pkg
adb shell setprop persist.vt.use_home_pkg <你的桌面包名>
```

如果你试了，欢迎把结果告诉我。
