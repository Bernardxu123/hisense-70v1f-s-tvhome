# 03 · 根权限通道

> ⚠️ 这一篇是「怎么在这台机器上拿到 root」。它利用的是**海信自带的 init 服务配置**，不是通用漏洞。
> 换固件、换机型大概率不适用。请只在自己的设备上使用，并清楚这是把双刃剑：它会一直存在，直到你删掉。

---

## root 是怎么来的

海信在 `/init.hisense.rc` 里定义了这样一个服务：

```
service autorun /system/bin/sh /system/bin/autorun.sh
    user root
    class main        # 没有 disabled → 每次开机都会执行
    oneshot
```

而 `/system/bin/autorun.sh` 的结尾是：

```sh
file_directory=/data/local/misc
file_location=/tmp
# ...
if [ -f $file_directory/Arun.zip ]; then
    busybox tar xvf $file_directory/Arun.zip -C $file_location
    chmod 777 $file_location/run.sh
    $file_location/run.sh
fi
```

于是链路是：

```
/data/local/misc/Arun.zip  (0777 目录，adb 可写)
        ↓ autorun 以 root 解开
/tmp/run.sh
        ↓ chmod 777 后执行
uid=0 的脚本
```

**注意 `Arun.zip` 其实是 tar 包**，不是 zip；里面的脚本必须叫 `run.sh`。

---

## 部署

本仓库 `scripts/` 里没有现成的 `Arun.zip`（它就是个 tar），自己打一个：

```powershell
# 1) 准备 run.sh（内容见下）
# 2) 打成 tar，命名为 Arun.zip
tar -cf Arun.zip run.sh          # Windows 10+ 自带 tar 即可

# 3) 推上去
adb push Arun.zip /data/local/misc/Arun.zip

# 4) 触发（不需要重启，也不需要 root）
adb shell setprop ctl.start autorun
```

`run.sh` 的最小内容（把实际动作放到 `/data/local/misc/rc.sh`，这样改动作不用重新打包）：

```sh
#!/system/bin/sh
R=/data/local/misc/rc.sh
if [ -f "$R" ]; then
  chmod 755 "$R"
  /system/bin/sh "$R" > /data/local/misc/rc.log 2>&1
  chmod 666 /data/local/misc/rc.log
fi
```

验证是否拿到 root：

```console
adb shell 'cat /data/local/misc/rc.log'
# id: uid=0(root) gid=0(root) context=u:r:hirpcdebugtools:s0
```

更直接的证据：root 脚本创建的文件属主是 `root`；它能读 `/data/misc/wifi`、`/cache` 这些 shell 读不到的目录。

---

## 为什么这条路能成

三个条件同时成立：

1. **服务以 root 运行**，且每次开机都跑；
2. **它从一个 0777 目录读文件**并执行 —— `/data/local/misc` 是 `drwxrwxrwx shell shell`；
3. **SELinux 是 permissive**，`setprop ctl.start autorun` 这类受控属性写入和 init 控制消息才会放行。

任何一个不成立，这条链就断了。

## 把桌面装成系统应用（root 之后最有用的动作）

这是主页键能被系统认下的关键一步。**目录和文件名都有讲究**：

```console
# 前提：已有 root（下面的命令放在 root 脚本里执行）
mount -o remount,rw /
mkdir -p /system/priv-app/TvHome
cp /data/local/tmp/TvHome.apk /system/priv-app/TvHome/com.local.tvhome.apk
```

- **APK 文件名必须等于包名**（`com.local.tvhome.apk`）。叫 `TvHome.apk` 会直接被拒：
  ```
  W PackageManager: Failed to parse /system/priv-app/TvHome: No packages found in split
  ```
- **目录权限要 0755**。用 root 的 shell 时 umask 可能是 077，会生成 `0700`，导致 shell 侧看不见。

```console
chown -R 0:0 /system/priv-app/TvHome
chmod 755 /system/priv-app/TvHome
chmod 644 /system/priv-app/TvHome/com.local.tvhome.apk
restorecon -R /system/priv-app/TvHome
sync
mount -o remount,ro /
```

如果之前用 `adb install` 装过同一个包，**先卸载**，否则 `/data` 的更新版本会盖住系统版本：

```console
adb uninstall com.local.tvhome
adb reboot      # 让系统重新扫描 /system/priv-app
```

确认：

```console
adb shell pm path com.local.tvhome
# package:/system/priv-app/TvHome/com.local.tvhome.apk
adb shell dumpsys package com.local.tvhome | grep -m1 flags=
# flags=[ SYSTEM HAS_CODE ALLOW_CLEAR_USER_DATA ]
adb shell cmd package query-activities --brief -a android.intent.action.MAIN -c android.intent.category.HOME
# priority=100 com.local.tvhome/.MainActivity
# priority=50  com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity
```

到这里，**实体遥控器按主页键就会直接进入 TvHome**（实测）。

---

## 为什么"风险可控"但仍要小心

- `/system` 是纯 ext4、没有 dm-verity，`remount,rw` 能成功，写入也快；
- 只**新增一个文件**、不覆盖、不删原有文件，最坏情况是被 PackageManager 跳过，不会导致开不了机；
- 但 **`adbd` 就在 `/system/bin/adbd`**，`/sbin` 里只有 `charger`/`ueventd`/`watchdogd`。
  一旦 `/system` 损坏到挂不上，**adb 也起不来**，远程恢复手段全部失效，只能靠 recovery / U 盘升级。

所以：动手前先备份。

```console
# 在 root 脚本里
tar -cf /data/local/tmp/priv-app-backup.tar -C /system priv-app
# 约 580 MB，之后可以 adb pull 到电脑
```

---

## 怎么删掉 root 通道

```console
adb shell 'rm -f /data/local/misc/Arun.zip /data/local/misc/rc.sh'
```

删掉之后：

- 开机不再执行任何自定义脚本；
- 已经装到 `/system/priv-app` 的桌面**仍然有效**（它跟钩子无关）；
- 但要再改系统文件就得重新部署钩子。

如果你连系统应用也想撤掉：

```console
# 在 root 脚本里
mount -o remount,rw /
rm -rf /system/priv-app/TvHome
sync && mount -o remount,ro /
adb reboot
adb install -r TvHome.apk     # 想继续用就装回普通应用
```
