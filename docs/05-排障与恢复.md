# 05 · 排障与恢复

## 一、先记住三个"不要"

1. **不要 `pm disable` 聚好看的桌面组件**（`com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity`）。
   会让开机永远走不完，而且没有 root 救不回来。
2. **不要在 `/system` 上做覆盖/删除操作**。`adbd` 就在 `/system/bin/adbd`，`/system` 坏了 adb 也没了。
3. **不要用 `input keyevent 3` 判断主页键行为**。这台固件会吞掉注入的按键，必须用实体遥控器。

---

## 二、症状对照表

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 开机卡在 logo 不动 | 聚好看桌面组件被禁用了 | 有 root：跑恢复脚本（下节）；没 root：只能恢复出厂 |
| 开机进了聚好看，没进自己的桌面 | 钩子没跑 / 触发太早 / 聚好看顶回去了 | 装 `debug` 标志看 `rc.log`；确认钩子在 `/data/local/misc/rc.sh` |
| `am start` 报 `Activity class ... does not exist` | 开机早期第三方包还不可启动 | 等 8–10 秒重试，属正常 |
| 主页键又回到聚好看 | 桌面不是系统应用，或 priority 没保住 | `query-activities` 看 priority；确认 `pm path` 指向 `/system/priv-app` |
| `adb` 连不上 | 电视待机 / IP 变了 / adbd 没起 | `adb connect <IP>:5555`；`persist.adb.tcp.port` 应为 5555 |
| 聚好看打不开（点了没反应） | 被 `force-stop` 了，正常 | 再点一次会冷启动；或重启电视 |
| 内存没省下来 | 用了 `am kill` 而不是 `am force-stop` | `am force-stop com.jamdeo.tv.vod` |

## 三、一键恢复默认桌面

`scripts/tv-recover-home.ps1`：重新启用聚好看组件 + 拉起 HOME intent。

```powershell
powershell -File scripts\tv-recover-home.ps1 -Serial 192.168.1.50:5555
```

它做的事等价于：

```console
adb shell 'pm enable --user 0 com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity'
adb shell 'am start -a android.intent.action.MAIN -c android.intent.category.HOME'
```

> 注意：这台机器上 `pm enable/disable` 必须由 **root** 执行（shell 会抛
> `SecurityException: Shell cannot change component state`）。所以恢复脚本是通过 root 钩子跑的，
> 单纯用 `adb shell` 执行上面两行是不行的。

## 四、抓日志的正确姿势

默认所有脚本都不写日志。要排查时：

```console
# 打开
adb shell 'touch /data/local/misc/debug'

# 复现问题（重启/按主页键）

# 看开机钩子的记录
adb shell 'cat /data/local/misc/rc.log'

# 看系统启动了什么
adb shell 'logcat -b system -d | grep "START u0" | grep -i home'

# 看当前前台
adb shell 'dumpsys activity activities | grep -m1 mResumedActivity'

# 关掉
adb shell 'rm -f /data/local/misc/debug /data/local/misc/rc.log'
```

## 五、诊断命令速查

```console
# HOME 候选与优先级
adb shell cmd package query-activities --brief -a android.intent.action.MAIN -c android.intent.category.HOME

# 当前会解析到谁
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME

# 桌面是不是系统应用
adb shell pm path com.local.tvhome
adb shell dumpsys package com.local.tvhome | grep -m1 flags=

# 开机有没有走完
adb shell getprop sys.boot_completed

# 聚好看进程与内存
adb shell ps -A | grep com.jamdeo.tv.vod
adb shell dumpsys meminfo com.jamdeo.tv.vod | grep -m1 TOTAL

# 钩子/守护进程在不在
adb shell 'ps -A -o PID,ARGS | grep -E "homewatcher|rc.sh" | grep -v grep'

# root 通道还在不在
adb shell 'ls -l /data/local/misc/Arun.zip /data/local/misc/rc.sh'
```

## 六、彻底恢复原状

```powershell
# 1) 撤掉开机钩子（root 通道）
adb shell 'rm -f /data/local/misc/Arun.zip /data/local/misc/rc.sh'

# 2) 撤掉系统应用（需要在 root 脚本里执行）
#    mount -o remount,rw /
#    rm -rf /system/priv-app/TvHome
#    sync && mount -o remount,ro /
#    然后重启

# 3) 想继续用桌面就装回普通应用
adb install -r launcher\TvHome.apk

# 4) 重启
adb reboot
```

最后确认：

```console
adb shell cmd package query-activities --brief -a android.intent.action.MAIN -c android.intent.category.HOME
# 应该只剩聚好看
```

## 七、最坏情况

`/system` 挂不上、adb 起不来：只能进 recovery（`hirecovery` 分区）或 U 盘升级。
**这台机器没有官方可下载的完整固件包**（对应的是 `His72691Upgrade.img`，04.02.60.03 版本），
所以写 `/system` 之前务必先 `tar` 备份——见 [03-根权限通道.md](03-根权限通道.md) 最后一节。
