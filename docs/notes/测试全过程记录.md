## 3. 逐项测试详情

### 阶段 A · 接入与画像（T01–T08）

#### T01 · 定位 adb

**现象**：`adb devices` 报"术语 'adb' 不会被识别"。

**处理**：搜索本机
```powershell
Get-ChildItem C:\Users -Filter adbkey.pub -Recurse   # 发现 C:\Users\29049\.android\adbkey (2026-10-01)
Get-ChildItem D:\ -Filter adb.exe -Recurse -Depth 3
```
**结果**：命中 `D:\software\开心电视助手8.1版本By剑心\Release\adb.exe`（该工具还自带 scrcpy、fastboot）。

#### T02 · 局域网扫描

```powershell
1..254 | ForEach-Object { Ping 192.168.31.$_ }        # 存活 9 台
foreach ($ip in $alive) { TcpClient 连 5555 }         # 只有 .234 开放
```
**结论**：电视 = `192.168.31.234`，MAC `A0-00-4C-32-74-BC`。

#### T03 · ADB 授权

**第一次**：`adb connect` → `failed to authenticate` / 设备状态 `unauthorized`。
**处理**：
```powershell
& $adb kill-server
& $adb connect 192.168.31.234:5555
```
**结果**：`device`。此后再未掉授权（含多次重启）。

#### T04–T06 · 画像与环境

```powershell
& $adb shell "getprop ro.product.brand; getprop ro.product.model; ..."
& $adb shell "cat /tvconfig/hisense.prop"
& $adb shell "cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME"
```

**关键发现**：
- `ro.product.model` 只是 `VIDAA_TV`，真实机型在 `/tvconfig/hisense.prop` → **70V1F-S**，`ro.vendor=novatek`，`ro.product.series=NT72691`。
- `ro.his.ad.adpath=/bootad/local/misc/` → 开机广告由固件播放。
- `ro.tv.dtv_support_type=dvbc_dtmb` → 有 DTV 调谐器（但用户不看直播）。
- `BLUETOOTH.Supported=false` → 无蓝牙。

#### T07 · 负载异常排查

`/proc/loadavg` 显示 **17.9**，看起来系统被压死。但：
```
vmstat 1 3 → r=0 b=0 us=3 sy=7 id=90 wa=0
```
**结论**：loadavg 是这颗 Novatek 内核的统计假象，**实际 CPU 90% 空闲**，不是性能问题。

#### T08 · 桌面相关属性

```

sys.home.display = 0
persist.sys.doublehome_support = （空）
ro.his.tv.launcher_version = V6LITE
```

### 阶段 D · 屏保改造实验（T23–T28）

**目标**：用户想要"以前那种黑底加时钟"的屏保。

#### T23 · 原状

```
settings get secure screensaver_components
→ com.google.android.deskclock/com.android.deskclock.Screensaver
settings get secure screensaver_enabled → 1
```
**关键**：`com.google.android.deskclock` **系统里根本没装** → 这条设置是死引用，等于"没有屏保"。

#### T24 · 改指 AerialDream

```powershell
& $adb shell "settings put secure screensaver_components app.orchard.tv/app.orchard.tv.dream.AerialDream"
& $adb shell "settings put secure screensaver_default_component app.orchard.tv/app.orchard.tv.dream.AerialDream"
& $adb shell "am broadcast -a app.orchard.tv.CONFIG -n app.orchard.tv/.guard.ConfigReceiver --ez own_screensaver true"
# Broadcast completed: result=0, data="keep_adb=false"
```

#### T25 · 尝试恢复固件 DeskClock（失败）

固件镜像里有 `app/DeskClock/DeskClock.apk`，manifest 里确实声明了
`com.android.deskclock.Screensaver`（DreamService）。但：

```powershell
& $adb install -r "D:\AI\杂\电视\_fw\apks\app__DeskClock__DeskClock.apk"
# → INSTALL_FAILED_INVALID_APK: Package couldn't be installed ...: code is missing
```
**根因**：该 APK 是**预编译（预优化）**的，包内**没有 classes.dex**，代码在系统分区的 `oat/arm/*.odex` 里 → 无法作为普通 APK 安装。

> 这个坑后来在别处复用：Aerial 的 APK 能改，正因为它带 dex。

#### T26–T27 · 海信自带屏保（拍信画册）

```powershell
& $adb shell "pm enable com.jamdeo.screensaver"
& $adb shell "settings put secure screensaver_components com.jamdeo.screensaver/com.jamdeo.screensaver.FlipperDream"
& $adb shell "am start -n com.jamdeo.screensaver/.DreamDisplayActivity"
```
**结果**：预览出来的是**风景照画册**（杭州雷峰塔那张），右上角一个 21:37 小字。
UI 里有四个标签：`画册 / 艺术画廊 / AI时钟 / 家庭相册`。

试 AI 时钟 → 卡在 **"AI插件加载中"**（依赖云端插件）。

**结论**：这是"拍信创意"的广告/内容屏保，不是黑底时钟；而且它的 `StartupImageDownloadService` 是**开机图/广告下载器**，启用它有副作用。

#### T28 · 按用户要求关闭屏保

```powershell
& $adb shell "pm disable-user --user 0 com.jamdeo.screensaver"
& $adb shell "settings put secure screensaver_enabled 0"
& $adb shell "settings put secure screensaver_components com.google.android.deskclock/com.android.deskclock.Screensaver"
```
**结论**：用户最终选择"不要屏保了"，保持 `screensaver_enabled=0`。

### 阶段 E · 桌面接管尝试（T29–T38）

这是整个项目耗时最长的部分，共 10 项，**全部失败或被拒**。

#### T29 · 改开机启动指针（部分有效）

```powershell

```

| 次数 | 结果 |
|---|---|
| 第 1 次重启 | ✅ **开机进 Aerial**；但该设置被改回 `com.jamdeo.tv.vod` |
| 第 2 次重启 | ✅ 又进 Aerial；这次设置**没有**被改回 |
| 用户手测 | ❌ 没有自动跳转 |

#### T31 · 追查 Aerial 是怎么起来的

```powershell
& $adb shell "logcat -d | grep -iE 'orchard|getHomes|initAppWhiteList'"
```
关键日志：
```
ActivityManager: getHomes:app.orchard.tv
ActivityManager: initAppWhiteList, App first white list for booting, add home package: app.orchard.tv
ActivityManager: START u0 {act=MAIN flg=0x10200000 cmp=app.orchard.tv/.MainActivity (has extras)} from uid 10042
UsageStatsService: notifyAppSwitch() App switch from:com.jamdeo.tv.vod to app.orchard.tv
```
**结论**：
- 固件确实把 Aerial 当成"home package"写进了开机白名单；
- Aerial 是**自己（uid 10042）**把自己拉到前台的（`guard.BootReceiver`）；

4. **v1 (JAR) 签名**：手写 `MANIFEST.MF` / `CERT.SF`，用 `cryptography` 的

#### T46 · 第二个补丁：`android:priority="60"`（失败）

用户提问："优先级是 50，是不是要把我们的桌面设得比 50 高？"

**思路**：给 Aerial 的 HOME intent-filter 加 `android:priority="60"`，压过聚好看的 50。

**实现要点**：
- 新增属性节点（20 字节），插在属性数组末尾
- 属性名 `priority` 需要资源 ID：从已有 `launchMode=0x0101001d` 反推 → **`android:priority = 0x0101001c`**
- 资源映射表（`RES_XML_RESOURCE_MAP_TYPE`）需要扩展到新字符串索引

**过程事故（T47）**：
- 第一次构建：属性插入偏移算错 **8 字节**（用了 `元素+24+attributeStart`，正确是 `元素+16+attributeStart`）
  → 安装报 `INSTALL_PARSE_FAILED_UNEXPECTED_EXCEPTION: Corrupt XML binary file`
  → 当时 Aerial 已被卸载 → **立即装回可用版本**（`aerial-standard-launcher.apk`）
- 用原始字节验证元素头后修正：`ResXMLTree_attrExt` 起始 = `元素+16`，属性数组 = `attrExt + attributeStart`
  （`headerSize=16`，`attributeStart=20`，`attributeSize=20`）
- 第二次构建：清单解析完全正确（`priority` → `dataType=16/INT_DEC, data=60`，`resmap[111]=0x0101001c`）

**结果**：
```powershell
& $adb shell "cmd package query-activities -a MAIN -c HOME --brief"
#   priority=50  com.jamdeo.tv.vod/...
#   priority=0   app.orchard.tv/.MainActivity     ← 仍然 0
```
**结论**：清单改对了但运行时被归零。

> **后续其他会话给出了正确答案**：海信 A9 框架对**第三方包**的 intent-filter priority
> **一律归零**（ATV Launcher 的 manifest 自带 `android:priority="951"`，运行时同样是 0；
> 只有系统包保留 50）。所以这条路**从根上不可能成功**。

#### T48 · 事故复盘

| 环节 | 问题 | 改进 |
|---|---|---|
| 卸载前 | 没有先在本地验证新 APK 可解析 | 应先用 `aapt`/自写解析器完整校验 |
| 偏移计算 | `+24` vs `+16` 混淆 | 用原始字节反推确认（已做，最终修正） |
| 风险控制 | 卸载后安装失败 → 应用真空 | 已准备可用版，30 秒内恢复 |

## 7. 可复用的方法与命令

### 7.1 无 root 改 Android APK 的唯一可行姿势（本机无 JDK）

```text
1. 解 AXML → 修改（字符串池追加 + 克隆已有节点保证结构合法）
2. 重打包 zip（保留 compress_type，剔除 META-INF）
3. v1 签名（Python cryptography）：
   MANIFEST.MF   = 每个条目的 SHA-256-Digest
   CERT.SF       = MANIFEST.MF 摘要 + 每个 section 的摘要
   CERT.RSA      = PKCS7(cert, key).sign(CERT.SF, DetachedSignature|NoAttributes)
4. adb uninstall <pkg> && adb install <patched.apk>   ← 签名变了必须卸
```
工具：`_scripts/patch_aerial_launcher.py`（加 LAUNCHER 类别）、`_scripts/patch_aerial_v2.py`（加 priority）。

### 7.2 AXML 结构备忘（踩过的坑）

```
文件头         : type=0x0003, headerSize=8, size=总长
字符串池       : 0x0001, hsize=28, flags(0x100=UTF8), stringCount, styleCount, stringsStart, stylesStart
资源映射       : 0x0180, 每项 u32；下标 = 属性名字符串索引 → 资源 ID
XML 节点       : 0x0102 开始元素 / 0x0103 结束元素 / 0x0100,0x0101 命名空间
开始元素       : node(16B) + attrExt(20B) + attrs(20B each)
   ! 属性数组起点 = 元素起始 + 16 + attributeStart（不是 +24！）
   ! attributeCount 在 元素起始 + 28
属性           : ns(4) name(4) rawValue(4) size(2) res0(1) dataType(1) data(4)
   INT_DEC = 0x10, STRING = 0x03
android:priority 资源 ID = 0x0101001c
```

### 7.3 判断"某个设置是不是我改的"

始终保留一份基线快照，然后：
```powershell
$old = Get-Content "$bk\settings-system-<ts>.txt"
$new = & $adb shell "settings list system"
Compare-Object $old $new
```
本会话正是靠它确认"直播键绑定不在 Android Settings 里"（三个域全无新增键）。

### 7.4 无 JDK 时的签名备选

- `cryptography`（Python）→ PKCS#7，本会话验证可用；
- Git for Windows 自带 `openssl 3.5.4` 亦可（`openssl smime -sign -noattr -binary`）。
