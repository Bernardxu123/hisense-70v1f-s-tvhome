## 0. 结论摘要（先看这段）

**免 root 换桌面在机制上可行，但唯一的可行路径会打掉聚好看的内容中枢能力。**

| 判断 | 内容 |
|---|---|
| 能否免 root 换桌面 | **能**——`pm uninstall -k --user 0 com.jamdeo.tv.vod` 后 HOME 候选只剩 ATV Launcher，priority 归零不再阻碍 **[本轮实测]** |
| 代价 | 聚好看 155 个组件全部失效；奇异果深链、投屏、语音、内容聚合依赖它 |

## 1. 本轮新增的决定性实测

### 1.1 推翻旧结论：`enabled=2` 不是 root 专属

旧报告《测试全过程记录》T34–T35 与 `handoff-for-other-ai.md` 均称：
> `enabled=2` 只能由 root/系统进程改，shell 只能管 `DISABLED_USER(3)`；5 种复活方式全败。

**实测过程 [本轮实测]**：

```
pm uninstall --user 0 com.android.settings            → Success
cmd package install-existing --user 0 com.android.settings → installed for user: 0
dumpsys package com.android.settings → enabled=0      ← 复活了
```

复活后 HOME 候选从 2 个变 3 个，`FallbackHome` 以 `priority=-1000` 出现：

```
priority=50    com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity
priority=0     ca.dstudio.atvlauncher/.screens.launcher.LauncherActivity
priority=-1000 com.android.settings/.FallbackHome          ← 新增
```

**原理**：`uninstall` 走 `deletePackageX()`，该路径**没有** ProtectedPackages 检查；
`install-existing` 重建包记录时 `enabled` 取 manifest 默认值（0），于是 `enabled=2` 这个用户态标记被清掉。

框架层证据（A8 镜像，`services.vdex`）：
`isPackageStateProtected()` 全框架只有 **3 个调用点**——

| 调用点 | 作用 |
|---|---|
| `setEnabledSetting()` | 拦 `pm disable/enable` |
| `setApplicationHiddenSettingAsUser()` | 拦 `pm hide` |
| `canSuspendPackageForUserLocked()` | 拦 `pm suspend` |

**`deletePackageX()` 不在其中**。

> ⚠️ 副作用：`enabled=2` 无法用 shell 精确还原（写 2 会被 setEnabledSetting 拦），只能还原成 `3`（`disabled-user`），行为等价。

### 1.2 核心突破：卸载 vod 后 ATV 成为唯一候选

用户授权 30 秒短窗口验证后执行 **[本轮实测]**：

```
pm uninstall -k --user 0 com.jamdeo.tv.vod        → Success

# 立即查解析
cmd package query-activities ... -c android.intent.category.HOME --brief
1 activities found:
  priority=0  ca.dstudio.atvlauncher/.screens.launcher.LauncherActivity   ← 唯一候选

# 立即还原
cmd package install-existing --user 0 com.jamdeo.tv.vod → installed for user: 0
```

还原后核对：

| 项 | 值 |
|---|---|
| `enabled` | `1`（先用 `pm enable` 从 manifest 默认 0 补回） |
| 组件数 | 155（与执行前一致） |
| 数据目录 | `/data/data/com.jamdeo.tv.vod` 存在（`-k` 生效） |
| HOME 候选 | 恢复为 vod(50) + ATV(0) |
| 前台 | ATV Launcher，用户界面未受影响 |

**为什么这条能成而 `pm disable-user` 不行**：
`pm disable-user com.jamdeo.tv.vod` 走 `setEnabledSetting` → 被 ProtectedPackages 拦；
`pm uninstall` 走 `deletePackageX` → 无此检查。

**"priority 归零"为什么不再是障碍**：
归零只影响**多候选排序**。候选只剩一个时，无论 priority 是 0 还是 -1000，它就是唯一解。

### 1.3 闭环 T38：preferred 写入 `mAlways=true` 仍无效

旧报告唯一未闭环项。本次用 ATV 重做 **[本轮实测]**：

```
cmd package set-home-activity --user 0 ca.dstudio.atvlauncher/.screens.launcher.LauncherActivity
→ Success
dumpsys package preferred-xml → 记录已是 ATV（含 MAIN + HOME + DEFAULT）

cmd package resolve-activity ... -c android.intent.category.HOME
→ priority=50  com.jamdeo.tv.vod/com.ju.main.launcher.LauncherActivity   ← 仍是聚好看
```

**结论**：preferred 记录在 `priority` 之后才参与决胜。`mAlways=true` 也没用，因为根本走不到那一步。
代码依据：`chooseBestActivity()` 先比 `priority`（`iget ResolveInfo->priority`）再调 `findPreferredActivity`。

### 1.4 社区方案在本机失效：`persist.vt.use_home_pkg`

GitHub `pengchujin/aerial-tv` 的机型文档记录了唯一免 root 成功案例：
> Android 11 / MT9653 机器，`adb shell setprop persist.vt.use_home_pkg app.orchard.tv` 后 HOME 键直达第三方桌面。

本机实测 **[本轮实测]**：

| 步骤 | 结果 |
|---|---|
| APK 内是否有该属性名 | ✅ `TvSettings_window.apk` 里确有 `persist.vt.use_home_pkg` |
| 引用点 | 仅 `CommonInterfaceHelper.setNewDoubleMeetings()`（写侧） |
| `setprop persist.vt.use_home_pkg ca.dstudio.atvlauncher` | `SET_EXIT=0`，值写入成功 |
| `resolve-activity` | ❌ 仍是 vod(50)，无任何变化 |
| 全盘扫描 framework/services.vdex | ❌ **完全不读该属性** |

**结论**：这是 Android 11 代固件新增的后门，本机（Android 9 / 04.02.60.03）没有对应实现。
本机确有 `persist.vt.*` 属性族（`all_firmware_ui_support` / `hi_freeze_mode` / `vod_run_mode` 等），但不含主屏幕选择。

### 1.5 排除"卸载 OTA 回退系统版"

现状聚好看是 OTA 装到 `/data/app` 的（versionCode 1500591603），`/system` 里还存着旧版（1500360598）。
直觉上"卸载更新 → 回退系统版 → 旧版 priority 可能是 0"。

实测解析系统版 manifest **[本轮实测]**：

```
/system/priv-app/SuperApp_YOUKU-red/SuperApp_YOUKU-red.apk
  LauncherActivity intent-filter priority='50'
```

**新旧两版都是 50**。海信在 2023 版就加了 priority，OTA 只是维持。这条路作废。

### 1.6 其它被排除的路径（本轮实测）

| 路径 | 实命令 | 结果 |
|---|---|---|
| `pm hide` | `cmd package hide --user 0 <pkg>` | ❌ `SecurityException: Neither user 2000 nor current process has android.permission.MANAGE_USERS` |
| `pm suspend` | `cmd package suspend --user 0 <pkg>` | ❌ `... has no android.permission.SUSPEND_APPS` |
| `cmd role` | `cmd role` | ❌ `Can't find service: role`（本机无 role 服务，与社区 C1 一致） |
| 双桌面开关 | `persist.sys.doublehome_support` | ⚠️ 实为**会议模式**开关（`CommonInterfaceHelper.isMeetingModeEnabled/setMeetingMode`），不是桌面切换 |
| `settings_startup_source_custom_pkg_key` | 社区文档明确记录"试过无效" | 与本地 T29 的"时灵时不灵"吻合 |
| `persist.sys.start_source` 改非物理源 | 反汇编 | ❌ 会走硬编码分支指向 `com.jamdeo.tv.livetv`，而该组件当前 `enabled=3` 且 resolve 返回 `No activity found` |
| Device Owner | `dpm set-device-owner` | ❌ 门槛 `device_provisioned=1` + `user_setup_complete=1` 已越，且本机无现成 `DeviceAdminReceiver`（仅 `Settings.apk` 声明） |

## 3. 路线评估矩阵

| # | 路线 | 机制是否成立 | 成本 | 风险 | 判定 |
|---|---|---|---|---|---|
| A | **卸载 vod 对该用户** + 装第三方 launcher | ✅ **已实测成立** | 10 分钟 | 中：内容中枢失效 | 可行但破红线 |
| B | **定制固件**（改 system.img 塞 priv-app / 改 services） | ✅ 技术可行 | 数天 | 高：变砖 | 唯一"完美"解 |
| C | 内核提权 → root | ⚠️ 无 public exploit 验证 | 数周 | 高 | 不推荐 |
| D | preferred / 属性 / 双桌面 / role / hide / suspend | ❌ 全部实测证伪 | — | — | 作废 |
| E | Aerial boot overlay 遮盖 | ✅ 只解决观感 | 1 天 | 低 | 配合 A 使用 |

### 3.1 路线 A 细化

**成立条件**：HOME 候选只剩 ATV（priority 归零不影响单候选）。

```bash
# 生效（重装前需确认 vod 数据目录存在，-k 保留数据）
adb shell pm uninstall -k --user 0 com.jamdeo.tv.vod
adb shell pm enable --user 0 ca.dstudio.atvlauncher
adb shell cmd package compile -m speed -f ca.dstudio.atvlauncher

# 还原
adb shell cmd package install-existing --user 0 com.jamdeo.tv.vod
adb shell pm enable --user 0 com.jamdeo.tv.vod
```

**必须接受的代价**（vod 有 155 个组件，不只是桌面）：

| 功能 | 影响 |
|---|---|
| 桌面/内容聚合 | 消失（这是目的） |
| 奇异果深链 `vod://detail` | **失效**——用户常用的奇艺内容跳转依赖 vod 的 `ContentDetail` |
| 投屏 4 件套 | 大概率失效（依赖 vod 的接收器） |
| 语音助手搜片 | 失效 |
| `BOOT_COMPLETED` / `HISENSE_BOOT_COMPLETED` 接收 | 无人接收（vod 是主要接收者） |

**未验证项**（本轮只做 30 秒短窗口，未重启）：
- 真实重启后开机是否真进 ATV
- 实体遥控器 HOME 键行为
- 断电/异常重启的恢复能力
- vod 卸载后系统是否触发看门狗或降级流程

**折中思路 [推断，未验证]**：卸载 vod → 重装为 data app（`adb install` 自己 manter 的 APK）。
重装后 vod 不再是系统包 → 若归零规则只豁免系统包，它可能降为 0，与 ATV 同为 0，此时 preferred 可以决胜。
**风险**：重装版丢失全部系统签名权限（`INSTALL_PACKAGES` / `WRITE_SECURE_SETTINGS` 等），vod 可能直接崩溃。
且 `/system/priv-app` 原 APK 仍在，`pm install` 的版本比较可能拒绝降级安装。

### 3.2 路线 B 细化（本轮新增关键情报）

此前判定"定制固件风险未知"，本轮把升级器的校验机制查清了一半 **[本轮实测]**：

**TIMG 容器头**（文件偏移 0）：`f8` 字段 = payload 总长，`[0x10:0x20]` = **payload 的 MD5**
```
md5(file[288:]) = 8fc72d852a3e5f528a8410b21a006dc6
头字段 [0x10:0x20] = 8fc72d852a3e5f528a8410b21a006dc6   ← 完全吻合
```

**PIMG 条目头 = 1160 字节**（此前误记为 288），`[0x10:0x20]` = **该条目 payload 的 MD5**：
```
6/6 条目全部吻合：
install_icon / part_tbl / eburner / board_info / panelparam / deviceinfo
```

**这意味着**：固件容器用的是**完整性校验（MD5），不是密码学签名**。
`uboot` 里虽有 `SHA256 is PASS` / `Authentication key` 字样，但：
- 未找到 MD5/SHA256 常量表（压缩镜像，静态扫不可靠）
- 无 `rollback` / `downgrade` / `anti-roll` 字符串 → **无反降级保护**
- `GPT ... signature is wrong` 里的 signature 指 GPT 头签名，与固件验签无关

**仍未知**（决定成败）：
- 升级器是否校验"条目清单完整性"（少一个条目会不会拒刷）
- 是否有未发现的 RSA 公钥（需动态调试或解压 uImage 才能确认）
- 刷写失败时的回滚路径（`hirecovery` 分区是否存在自动恢复）

**结论**：门槛比原判断低（可重算 MD5 重打包），但仍不适合在没有 U 盘急救验证的情况下贸然尝试。

### 3.3 为什么路线 C 不推荐

| 项 | 实测值 | 含义 |
|---|---|---|
| 内核 | Linux 4.9.118+（2024-02-20 编译）· armv7l | 老内核，理论漏洞多 |
| SELinux | `Permissive` | 提权后无需二次突破 |
| KASLR | `randomize_va_space=2` | 有 ASLR |
| `kptr_restrict` | `2` | 拿不到内核符号 |
| `dmesg_restrict` | `0` | dmesg 可读（唯一有利项） |
| `CONFIG_HARDENED_USERCOPY` | `y` | 加固开启 |
| `CONFIG_SLAB_FREELIST_RANDOM` | 未设 | 堆布局可预测（有利） |
| `/dev/mem` | 不存在 | 无直接物理内存口 |
| 分区写权限 | 全部 `NOT_WRITABLE`（shell） | 拿到 root 前改不了任何分区 |

无公开的 NT72691 exploit；自己写 ARM32 内核 exploit 的工作量（数周）与收益（只是达到路线 A 的效果）不匹配。

## 4. 关键技术附录

### 4.1 开机 → 桌面的真实路径（复核 A8 反汇编）

```
AMS.startHomeActivityLocked()
 ├─ getHomeIntent + resolveActivityInfo  → 先解析一次，若为 null 走 "No home screen found"
 ├─ HisenseStartManagerUtil.readFactoryProperty()
 ├─ isFteOrFactoryMenuStart() / isStartHotelHome()
 ├─ HisenseStartManagerUtil.isStartPhysicalSource()
 │    └─ getStartUpInputSource()：读 persist.sys.start_source(默认2)，
 │       为 0 时改读 persist.sys.last_source；命中 2562/2304/2305 → true
 ├─ [true]  → ActivityStarter.startHomeActivityLocked()   ← 真机走这条（last_source=2562）
 │             → AOSP 标准 category.HOME 解析（priority 决胜）
 └─ [false] → 海信硬编码显式组件：
               FTE(com.android.tv.settings/…fte.MainActivity) → 工厂(uifac) → 酒店(hotelmenu)
               → 默认 com.jamdeo.tv.livetv/.LiveTvActivity
```

**关键**：`persist.sys.start_source` 属性 **shell 可写**（实测 0→1→0 成功）。
但把它改成非物理源只会指向 `livetv`，而该组件 `enabled=3` 且 resolve 返回 `No activity found` → 负收益。

### 4.2 开机白名单（复核，未用于攻击）

`AMS.initAppWhiteList()` 读 `/data/local/misc/app_start_when_boot_whitelist.txt`（优先）或 `/system/etc/...`。
`1:` = 开机可启动白名单，`2:` = 另一组。文件为空时追加**所有 HOME 候选包**。

本机 `/data/local/misc` 权限 `drwxrwxrwx`（**无 sticky 位**），shell 可 **rename** 其中的 `system:system 600` 文件
（实测可 rename 后立即 rename 回来），但**不可写其内容**（`cp` / `touch` 均 Permission denied）。

**语义**：这是"允许谁在开机阶段启动"，不是"指定启动谁"，**不能用来指定桌面**。
且 `isAppInFirstWhiteList` 在 framework 内无调用点（仅日志字符串）→ 实际用途待查。

### 4.3 cdex 解析器（本轮完成）

真机 A9 的 `framework/services.vdex` 是 compact-dex（`vdex019`），`_fw` 原有工具只认标准 dex。
本轮摸清了 cdex 头部布局，可到"类/方法级"定位：

```
cdex header 0x88 字节（偏移相对 cdex 基址）：
  +0x20 file_size    +0x24 header_size
  +0x38/+0x3C str_ids size/off    +0x40/+0x44 type_ids
  +0x48/+0x4C proto_ids           +0x50/+0x54 field_ids
  +0x58/+0x5C method_ids          +0x60/+0x64 class_defs
  +0x68/+0x6C data size/off

表偏移链自校验（6 组严格连续）：
  str  + 4*n == type     type  + 4*n == proto    proto + 12*n == field
  field+ 8*n == method   method+ 8*n == class    class + 32*n == data - 4
string_ids 项直接指向 MUTF-8 内容（无 uleb 长度前缀），命中率 89.7%
```

未完成：`class_defs + 32*n` 与 `data_off` 差 4 字节（可能有未识别的对齐字段）。
真机 `dexdump` **不认 cdex**（`Failed structural verification`），所以自建解析器是唯一途径。

### 4.4 可借用社区的两处工程实践

1. **记录原值再改**：aerial-tv 的 `install.sh` 把 `persist.vt.use_home_pkg` 原值存进
   `settings global aerial_vt_home_pkg`，`restore.sh` 读它还原。这个习惯值得照搬。
2. **boot overlay 遮盖**：用 `TYPE_ACCESSIBILITY_OVERLAY` 盖住开机闪屏（见 §2.2 issue #423）。

## 6. 建议

### 如果目标是"用 ATV Launcher，且接受失去聚好看内容"

1. 先做完整备份（数据目录 + 当前设置）
2. 按 §3.1 执行 A，**保留 `-k`**
3. 重启验证开机行为（本轮未做）
4. 准备好还原命令，随时可 `install-existing` 回来

### 如果目标是"完美替换，不损失任何功能"

**只有路线 B（定制固件）**。最小改动方案：
- 在 `system.img` 的 `/system/priv-app/ATVLauncher/` 放入 ATV 的 base.apk
- 让它成为特权系统应用 → priority 951 **可能**豁免归零（需先验证归零规则是否只针对非系统包）
- 重算 system.img 的 MD5 → 回填 TIMG 与 PIMG 头 → 重打包
- ⚠️ **必须先验证升级器是否接受重打包镜像**（U 盘刷写测试，且准备好 `hirecovery` 应急）

在动手前需要先解决：ATV 是第三方签名，放进 priv-app 需要 `platform` 签名或允许其以非平台签名运行。

### 如果维持现状

保持"开机进聚好看 + 红键/直播键进 ATV"的妥协方案。本轮所有实验都可回收，没有留下任何不可逆状态。
